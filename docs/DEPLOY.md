# Deploying Diorama Maker (free tier)

## 1. Overview

- Frontend: static site on Netlify (free).
- Backend: Spring Boot in a Docker container on Render (free web service). The `render.yaml` blueprint in the repo root describes it.
- Data: your existing Supabase project (Postgres + file storage).
- AI: Gemini free tier. `TRIPO_MODE` stays `mock` (live Tripo needs paid credits).
- Netlify proxies `/api/*` to Render. `frontend/scripts/write-redirects.mjs` writes `dist/_redirects` at build time from `API_ORIGIN`. The browser sees one origin, so no CORS is needed and share links and `/api/files` URLs just work.

```
browser -> Netlify (static + /api proxy) -> Render (Spring Boot) -> Supabase (Postgres + Storage bucket), Gemini
```

## 2. Before you start

1. Accounts: GitHub (you have it), Render, Netlify. Render and Netlify both sign in with GitHub, no card.
2. In Supabase, copy the **Session pooler** connection string (Project settings > Database). Render has no IPv6 and Supabase's direct host is IPv6-only, so the direct host will not work.
   - `SUPABASE_DB_URL` = `jdbc:postgresql://aws-...pooler.supabase.com:5432/postgres`
   - `SUPABASE_DB_USER` = `postgres.<project-ref>`
   - `SUPABASE_DB_PASSWORD` = your database password
3. In Supabase Storage, make a **public** bucket named `models` (or use another name and set `SUPABASE_BUCKET`).
4. Note `SUPABASE_URL` (Project settings > API) and the service key `SUPABASE_SERVICE_KEY` (service_role key; keep it secret).

## 3. Backend on Render

1. Render dashboard > New > Blueprint. Pick the repo and the branch. Render reads `render.yaml`.
2. Fill the values marked `sync: false`: `GEMINI_API_KEY`, `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`, `SUPABASE_DB_URL`, `SUPABASE_DB_USER`, `SUPABASE_DB_PASSWORD`, `FRONTEND_ORIGIN`.
   - `FRONTEND_ORIGIN` is the Netlify URL, e.g. `https://<site>.netlify.app`. If you do not know it yet, put a placeholder and fix it in step 5.
3. `IP_HASH_SALT` and `ADMIN_TOKEN` are generated by Render. `STORAGE_MODE=supabase` is preset (Render's disk is wiped on every deploy and spin-down).
4. Apply. The first deploy builds the Docker image and takes several minutes. Flyway migrations V1 to V5 run at start and are additive.
5. Open `https://<service>.onrender.com/api/health`. It should answer OK.
6. The free plan sleeps after 15 minutes idle. The first request after that takes about a minute (the waiting screen covers it).

## 4. Frontend on Netlify

1. Netlify > Add new site > Import from Git > pick the repo.
2. `netlify.toml` already sets base `frontend`, the build command, publish `dist` and Node 24. Leave the form as it is.
3. Site configuration > Environment variables: add `API_ORIGIN` = `https://<service>.onrender.com` (https, no trailing slash, no path).
4. Deploy. Open the site. The gallery should load (the first load may be slow while Render wakes up).

## 5. Connect the two

1. On Render, set `FRONTEND_ORIGIN` to the Netlify URL. Several are comma-separated, e.g. `https://mydomain.com,https://<site>.netlify.app`.
2. Redeploy the backend (Manual Deploy, or save the env var and let Render restart it).
3. Custom domain: add it in Netlify (Domain management), then add it to `FRONTEND_ORIGIN` too.

## 6. Check after deploying

1. Create a story from a computer, then one from a phone on mobile data. Each address has its own count (5 stories per address per day, 20 tweaks per day).
2. If both count together, the proxy hop count is wrong. `TRUSTED_PROXY_HOPS=2` assumes Netlify's proxy then Render's. Set it to `1` if you call Render directly without Netlify.
3. A story plays with the generated narrator voice. `GEMINI_TTS=off` falls back to the browser voice.
4. The gallery shows the picture after the creator has watched the story once.
5. Video download works in desktop Chrome, Edge and Firefox.

## 7. Settings reference

| Variable | Where | Default | Meaning |
|---|---|---|---|
| `TRIPO_MODE` | Render | `mock` | `mock` or `live`; live spends real Tripo credits |
| `GEMINI_API_KEY` | Render | empty | Gemini key; without it the offline planner is used |
| `GEMINI_MODEL` | Render | `gemini-3.5-flash-lite` | Model for story planning |
| `GEMINI_TTS` | Render | `on` | Generated narrator voice; `off` uses the browser voice |
| `GEMINI_TTS_MODEL` | Render | `gemini-3.8-flash-tts` | Speech model |
| `GEMINI_TTS_VOICE` | Render | `Kore` | Narrator voice name |
| `GEMINI_TTS_DAILY_LIMIT` | Render | `150` | Daily cap on speech requests |
| `STORAGE_MODE` | Render | `auto` (blueprint: `supabase`) | `auto`, `supabase` or `local` |
| `SUPABASE_URL` | Render | empty | Supabase project URL |
| `SUPABASE_SERVICE_KEY` | Render | empty | Service key for Storage |
| `SUPABASE_BUCKET` | Render | `models` | Storage bucket name |
| `SUPABASE_DB_URL` | Render | empty | JDBC session pooler URL |
| `SUPABASE_DB_USER` | Render | empty | `postgres.<project-ref>` |
| `SUPABASE_DB_PASSWORD` | Render | empty | Database password |
| `FRONTEND_ORIGIN` | Render | `http://localhost:5173` | Allowed site address(es), comma-separated |
| `TRUST_PROXY` | Render | `false` (blueprint: `true`) | Read visitor address from `X-Forwarded-For` |
| `TRUSTED_PROXY_HOPS` | Render | `1` (blueprint: `2`) | Proxies that append to `X-Forwarded-For` |
| `MAX_STORIES_PER_IP_PER_DAY` | Render | `5` | New stories per address per day |
| `MAX_TWEAKS_PER_IP_PER_DAY` | Render | `20` | Tweaks per address per day |
| `THUMBNAIL_UPLOADS` | Render | `true` | Gallery pictures sent by the creator's player |
| `IP_HASH_SALT` | Render | generated | Salt for hashing addresses |
| `ADMIN_TOKEN` | Render | generated | Protects `GET /api/credits` (header `X-Admin-Token`) |
| `PORT` | Render | `8080` | Set by Render, do not touch |
| `API_ORIGIN` | Netlify (build only) | none | Render address that `/api/*` is proxied to |

## 8. Limits and costs

- Everything is on free tiers: 0 EUR.
- Render free: 512 MB RAM, 750 instance hours per month, sleeps after 15 minutes idle.
- Netlify free: 100 GB bandwidth per month.
- Supabase free: 500 MB database, 1 GB storage, project pauses after a week idle (resume it in the dashboard).
- Gemini free tier quotas (planner, speech, thumbnail check) are per project and not published. The app guards with daily caps.
- Nothing here was deployed or run by the author of this document. Docker is not installed on the development machine, so the Dockerfile and this procedure were checked by reading only. Expect to fix small things on the first try.

## 9. Alternatives

Cloudflare Pages and GitHub Pages cannot proxy `/api` to another host the same way. With them you would set `FRONTEND_ORIGIN` and serve the API from its own domain, which needs code changes for absolute file URLs (not done).
